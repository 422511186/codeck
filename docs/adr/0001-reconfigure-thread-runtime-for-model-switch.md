# 模型切换统一重配会话运行时

模型切换统一由一个 codeck 后端命令通过重新载入同一个 thread 来重配运行时，同时保留 thread ID 与完整历史。没有采用仅更新 thread settings、只对自定义模型重配或由浏览器串联底层请求的方案，因为模型切换还必须同步当前 `model_provider`、上下文窗口、能力约束和会话模型绑定，并在 unsubscribe 或 resume 失败时恢复到确定状态；统一流程可以避免从自定义模型切回 app-server 模型时残留旧配置，并允许核验 app-server 实际采用的模型。

## Consequences

模型切换只能在会话空闲且运行时可以安全重新载入时完成。后端命令必须在会话锁内校验目录修订号、当前模型选择身份、reasoning 档位和绑定版本；过期请求返回冲突且不能自动重试。通过校验后，命令还必须处理取消订阅、resume 结果核验、会话模型绑定的提交或恢复、失败后的旧配置恢复和前端状态重新同步，并返回切换成功、已恢复或恢复失败的明确结果，不能被视为单纯修改选择器值。

每次切换或重新应用使用稳定的 `operationId` 关联请求、运行时步骤与终态审计。审计记录来源敏感的旧/新模型选择、reasoning、上下文窗口、当前 provider 标识以及 `switched`、`recovered` 或 `recovery_failed` 结果，但不能包含凭据或完整 provider 配置。

HTTP 终态与业务结果保持固定映射：目标生效返回 `200 switched`；尚未执行的忙碌、前置状态过期或容量冲突返回 `409`；目标失败但旧状态恢复成功返回 `502 recovered`；目标与旧状态都无法可靠恢复返回 `500 recovery_failed`。所有非成功响应返回稳定错误码、`operationId` 和后端确认的最新会话状态。前端只有在 `switched` 时采用目标选择；`recovery_failed` 时必须禁用发送，不能根据错误文本猜测状态。

处于 `recovery_failed` 的会话保留历史与草稿，并提供“恢复原模型”和“重试目标模型”两个命令。前者使用操作记录中的旧状态，后者使用操作记录中的目标快照而不重新解析可能已经变化的目录配置；两者都重新读取当前 provider、执行空闲检查与完整核验。任一命令成功后提交对应绑定并清除操作记录，再次失败则维持阻塞，不提供忽略错误后继续发送的路径。
