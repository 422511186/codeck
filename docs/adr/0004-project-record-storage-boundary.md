# 项目记录存储边界

> 状态：已接受。

## 背景

登录后的首屏是工作区项目列表。当前新增工作区后，浏览器只把项目记录写入
`localStorage`；后端只负责校验 `cwd` 并访问该目录，不维护项目目录清单。

本次需求的目标是让项目记录可以跨设备可见，同时保留仅在当前浏览器保存的选项。

## 已确认的边界

- 本次同步对象是项目记录，而不是工作区中的文件内容。
- 项目记录至少包含现有的名称、路径、创建时间和最近使用时间等元数据。
- 工作区文件仍由后端工作区和 Codex app-server 管理，不引入文件上传、复制或双向文件同步。
- 存储位置是项目记录的属性：一个项目可以只保存在客户端，也可以保存在服务端。
- 服务端项目记录以后端实例为共享范围；所有通过同一个个人访问 token 登录该实例的设备看到同一份记录。
- 当前个人模式不为项目记录引入用户 ID、多用户隔离或账号级权限模型。
- 每条项目记录只有一个权威存储位置：仅客户端项目只持久化到 `localStorage`，服务端项目只持久化到服务端。
- 项目页分别读取客户端项目和服务端项目，再在内存中合并展示；浏览器不为服务端项目维护持久化镜像。
- 修改存储位置表示移动记录而不是复制记录，移动前后保持同一个项目 ID。
- 移动时先写入目标存储，成功后再删除源记录；目标写入失败时必须保留源记录。
- 服务端项目移动到客户端后，只保留在发起操作的浏览器中，并从其他设备的共享列表消失。
- 新增项目的默认存储位置由 Web 端“设置”页面配置，不使用部署环境变量决定。
- 默认项目存储位置由服务端持久化，并以后端实例为范围在所有已认证设备间共享。
- Web 设置页负责读取和修改该服务端设置；它不属于浏览器本地偏好。
- 服务端尚未保存默认项目存储位置时，初始值为服务端；新增表单仍允许对当前项目改选为仅客户端。
- 版本升级不自动迁移已有 `localStorage` 项目；它们继续是仅客户端项目，必须由用户显式移动到服务端。
- 同一个规范化工作区路径在客户端与服务端合并目录中只能对应一条项目记录。
- 新增或移动项目时，如果另一存储已经存在相同路径，系统必须进入冲突处理，不能创建重复记录。
- 同路径冲突通过显式选择解决：保留服务端、保留当前设备，或取消；系统不得静默覆盖或删除任一记录。
- 服务端项目的改名、存储位置移动和删除采用目录级乐观并发控制；客户端提交读取时的 catalog revision，过期写入返回冲突并刷新最新目录。
- 服务端不得用无提示的最后写入覆盖处理项目元数据冲突。
- 服务端项目的 `lastUsedAt` 和由此产生的排序在实例内跨设备共享。
- 多设备更新 `lastUsedAt` 时只保留较晚时间，不把这种高频、可合并更新作为人工版本冲突。
- 服务端项目目录读取失败时，项目页继续展示并允许使用仅客户端项目，同时显示可重试的服务端错误。
- 服务端目录不可用期间，客户端可以新增仅客户端项目，但必须禁用服务端项目的新增和变更。
- 服务端读取失败不得被解释为服务端项目列表为空，也不得用浏览器持久化镜像冒充最新服务端数据。
- 从列表移除项目只删除项目记录：客户端项目只从当前浏览器删除，服务端项目从共享目录删除。
- 移除项目不得删除工作区目录、目录内容或任何 Codex thread。

## 实施提示

- 服务端项目目录和默认设置使用 `CODEX_WEB_DATA_DIR/projects.json`，沿用原子写入与文件锁模式。
- 具体 HTTP 路由、字段版本和界面布局属于实现细节，必须保持本 ADR 的权威存储与冲突语义。
