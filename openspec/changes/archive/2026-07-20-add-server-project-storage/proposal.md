## Why

当前工作区项目记录只保存在浏览器 `localStorage`，用户更换设备或浏览器后必须重新添加项目，且项目别名和最近使用顺序无法同步。需要在保留“仅当前设备”选择的同时，引入服务端项目目录，让同一后端实例上的设备共享用户明确选择保存到服务端的项目记录。

## What Changes

- 为项目记录增加 `client` 与 `server` 两种权威存储位置，项目页合并两边数据展示，但不为服务端记录维护浏览器持久化镜像。
- 新增服务端项目目录及认证 API，持久化项目记录、共享默认存储位置和并发 revision，并沿用 `CODEX_WEB_DATA_DIR`、原子 JSON 写入与文件锁。
- 新增项目默认保存到服务端；默认值在 Web 设置页修改并由服务端跨设备共享，新增弹窗允许针对当前项目改选。
- 项目管理支持保留项目 ID 的显式存储位置移动；升级后已有本地项目不自动上传。
- 规范同路径冲突、乐观并发、全局最近使用时间、服务端失败时的部分降级，以及只删除记录而不删除目录或会话的行为。
- 项目列表与项目会话页能够解析服务端项目；服务端项目在任一设备进入后共享最近使用排序。

### Modified Capabilities

- `project-management`: 将仅浏览器项目列表扩展为客户端/服务端双存储目录，增加跨设备共享、迁移、冲突、并发与降级规则。
- `settings-minimal`: 在 Web 设置页增加由服务端持久化的默认项目存储位置，并用于初始化新增项目表单。

## Impact

- 新增 `src/server/projects/` 持久化目录、`/api/codex/projects*` API 和共享项目类型。
- 修改 `src/web/storage/projects.ts`、Web API client、项目列表页、项目会话页和设置页。
- 更新项目与设置相关 Vitest 单元测试，并新增服务端目录和 route 测试。
- `CODEX_WEB_DATA_DIR` 将新增版本化 `projects.json`；不新增数据库或第三方依赖。
- 现有 `localStorage` 项目保持兼容并继续视为仅客户端项目，不发生自动迁移。
