## Context

当前项目列表由 `src/web/storage/projects.ts` 同步读写浏览器 `localStorage`，项目页以本地随机 ID 路由到工作区会话列表。后端只通过 workspace allowlist 校验 `cwd`，没有项目目录概念。项目使用个人 token 登录，同一后端实例不存在用户 ID 或多租户隔离。

仓库已有适合复用的服务端持久化模式：`CODEX_WEB_DATA_DIR`、版本化 JSON 文件、进程间文件锁、原子替换写入、认证 route、审计日志和 409 revision 冲突响应。本变更跨越共享类型、服务端持久化、HTTP API、客户端存储、项目页、项目会话页、设置页和测试。

## Goals / Non-Goals

**Goals:**

- 让用户按项目选择仅客户端或服务端权威存储，并在同一后端实例的设备间共享服务端项目。
- 在项目页合并展示两种项目，保持现有路径校验、项目会话聚合、重命名、排序和移除体验。
- 支持保留项目 ID 的显式存储位置移动、路径冲突处理和多设备乐观并发。
- 在 Web 设置页维护服务端共享的默认项目存储位置，初始值为服务端。
- 对旧 `localStorage` 数据兼容，且服务端目录失败时客户端项目仍可用。

**Non-Goals:**

- 不同步、上传、复制或删除工作区文件。
- 不迁移或删除 Codex threads，不改变 app-server 对会话的持久化职责。
- 不引入数据库、用户账号模型、多租户隔离或公网权限系统。
- 不自动上传升级前的客户端项目，不为服务端项目维护浏览器持久化镜像。

## Decisions

### 1. 使用一个版本化服务端项目目录

在 `CODEX_WEB_DATA_DIR/projects.json` 保存 `schemaVersion`、`revision`、`defaultStorage` 和服务端项目数组。文件权限、原子写入和锁策略复用自定义模型目录实现。

采用 JSON 文件而不是数据库，因为当前是单实例个人模式，已有部署和备份约定都围绕 `CODEX_WEB_DATA_DIR`。单独文件也避免把项目偏好写入 Codex app-server 配置。

### 2. 人工变更使用 catalog revision，最近使用时间使用单调合并

创建、重命名、删除、修改默认存储位置都携带 `expectedRevision`；过期请求返回 HTTP 409、稳定错误码和最新完整目录。任一成功人工变更递增 revision。

进入服务端项目时更新 `lastUsedAt`，在文件锁内仅接受更大时间且不递增 revision。这样高频排序更新不会使不相关的重命名或删除持续冲突，同时不会回退全局最近使用时间。

### 3. 每条记录只有一个权威存储

客户端项目只写 `localStorage`，服务端项目只写 `projects.json`。项目页读取本地项目和服务端目录后在 React 状态中合并排序。服务端加载失败时显示错误和重试，继续提供客户端项目与新增客户端项目能力，不使用持久化缓存冒充服务端数据。

旧本地记录读取时补充 `storage: "client"`，不自动调用服务端创建接口。

### 4. 路径是跨存储的业务唯一键

服务端 route 在创建前使用 `assertAllowedPath` 得到 allowlist 内的规范化路径；目录 store 使用 Windows 大小写不敏感、POSIX 大小写敏感的路径 key 防止服务端重复。前端合并时用同一规则检测客户端/服务端碰撞。

检测到跨存储同路径时只渲染一个冲突状态，由用户选择保留服务端、保留当前设备或取消。系统不得自动覆盖别名或删除记录。

### 5. 存储位置修改是可回滚移动

客户端转服务端时，以原 ID 和时间字段创建服务端记录，成功后删除本地记录。服务端转客户端时，先保存本地记录，再按 revision 删除服务端记录；若删除失败则移除刚写入的本地目标记录，恢复单一权威状态。

目标写入、源删除或回滚任一步失败时显示明确错误并重新读取权威数据。移动不是复制，服务端转客户端会让其他设备不再显示该项目。

### 6. API 与页面职责

- `GET/POST /api/codex/projects`：读取目录和创建服务端项目。
- `PUT/DELETE /api/codex/projects/:projectId`：重命名和移除服务端记录。
- `POST /api/codex/projects/:projectId/touch`：单调更新全局最近使用时间。
- `PUT /api/codex/projects/default-storage`：修改共享默认值。

所有 route 要求 Web session 认证，创建路径必须经过 workspace allowlist，人工变更记录审计但不记录目录内容。项目页负责合并、冲突 UI 和移动编排；项目会话页在本地查找失败后读取服务端目录解析项目 ID。

### 7. 设置页只管理新增默认值

设置页新增“项目”分组和客户端/服务端选择器，通过项目目录 API 读写 `defaultStorage`。该值只初始化新增弹窗，不移动已有项目。目录首次创建时默认 `server`。

## Risks / Trade-offs

- [catalog revision 会让不同项目的同时人工修改冲突] → 个人模式下人工修改低频；409 返回完整目录，客户端刷新后可重试，换取简单可审计的一致性模型。
- [服务端转客户端需要跨浏览器存储和 HTTP 的补偿事务] → 先写目标、再删源，源删除失败时立即删除本地目标并刷新；测试覆盖每个失败点。
- [客户端旧路径可能与其他设备创建的服务端路径碰撞] → 不自动迁移或删除，显示显式冲突选择。
- [项目目录文件损坏会使服务端项目不可用] → 失败关闭并保留原文件，客户端项目部分降级可用，运维可从 `CODEX_WEB_DATA_DIR` 备份恢复。
- [同一 token 的所有设备共享项目路径元数据] → 这是现有个人实例认证模型的明确边界；不声称提供用户级隔离。

## Migration Plan

1. 部署包含 `projects.json` store 和 API 的后端；首次读取时原子创建空目录，默认存储位置为服务端。
2. 发布兼容旧 schema 的前端，本地项目读取时补充 `storage: "client"`。
3. 项目页开始合并服务端目录；已有本地项目保持原状并可逐个移动。
4. 回滚前端时服务端 `projects.json` 保留但旧前端忽略；回滚后端前应先确保新版前端不再调用项目 API。
