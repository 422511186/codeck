## Context

当前次要操作入口高度依赖长按：

- 项目列表：长按 → 底部 sheet（重命名 / 存储迁移 / 移除）
- 会话列表：长按 → 底部 sheet（归档 / 移出归档）；进行中与已归档均可点击进入会话
- 用户消息：长按 → 底部 sheet（复制 / 回滚 / Fork）
- 会话页顶栏：已有显式 `⋮` → sheet（重命名 / 归档 / 压缩），归档带 Undo Toast

约束：默认界面保持干净（不用每行 `⋯`、不用顶栏「管理」模式）；已归档会话不能进入聊天；可逆操作避免多余确认弹窗，但左滑必须「滑出按钮后再点」才执行。

## Goals / Non-Goals

**Goals:**

- 用可发现、可预期的入口替代长按主路径
- 会话列表：左滑归档/移出；归档 tab 点击出 sheet 移出；已归档不可进入
- 项目列表：纯导航；项目操作进入项目后管理
- 用户消息：轻点出工具条
- 复用既有 archive/unarchive API 与会话内 Undo Toast 模式
- 共享可复用的移动端交互原语（左滑行、sheet、toast）

**Non-Goals:**

- 不改后端 archive/unarchive/rename API 契约
- 不做批量多选管理
- 不做桌面端布局
- 不引入重型手势库（优先轻量 pointer 实现）
- 不重做会话页顶栏 `⋮` 体系（仅保持语义一致）

## Decisions

### D1. 会话列表用左滑 + 归档 tab 点击 sheet

- **选择**：进行中左滑露出「归档」再点执行；已归档左滑露出「移出归档」再点执行；已归档整行点击打开 sheet（移出 / 取消），不直接移出、不进入会话。
- **备选**：顶栏「管理」编辑态（用户否定）；每行三点（用户否定）；点击直接移出（用户否定）。
- **理由**：默认列表干净；已归档不能进入后，点击语义可安全让给操作 sheet；左滑两步满足二次确认而不弹窗。

### D2. 已归档禁止进入会话

- **选择**：已归档 tab 下条目的主点击 MUST NOT 路由到 `/threads/:id`。
- **理由**：产品规则明确；进入路径关闭后，列表侧移出归档成为唯一恢复路径（配合左滑与 sheet）。
- **连带**：`thread-list-view` 中「从已归档进入会话再返回」类场景改为不适用或改为「从 sheet 取消后仍停在已归档 tab」。

### D3. 项目操作收纳到项目内

- **选择**：项目列表移除长按；在项目会话列表页提供克制的项目设置入口（例如标题区可点或设置图标），打开与原菜单等价的 sheet（重命名 / 存储迁移 / 移除）。
- **备选**：列表左滑项目操作（项目管理低频，且与会话列表手势语义混杂）。
- **理由**：列表保持纯进入；操作发生在用户已表达关注的项目上下文。

### D4. 用户消息轻点工具条

- **选择**：轻点 user message 气泡 → 选中态 + 贴近气泡或底部的操作面板（复制 / 回滚 / Fork / 取消）；运行中仅允许复制。
- **备选**：保留长按；气泡旁常驻 `⋯`。
- **理由**：可发现且不与「长按选字」主路径抢；复制/回滚/Fork 业务语义不变，只换入口。
- **细节**：点气泡空白/主体出工具条；系统文本选择仍可用（用户主动拖选）；再次点击空白或取消关闭。

### D5. 可逆操作用按钮确认 + Undo Toast，不用确认对话框

- **选择**：归档 / 移出归档：滑出按钮点击 或 sheet 选项点击后立即请求；成功后可选 Undo Toast（对齐 `thread-controls` 归档体验）。
- **回滚**：保持高影响确认（若现有无对话框，至少保持明确点击意图，不自动触发）。
- **项目移除**：保留危险色 + 明确确认。

### D6. 实现结构

- 抽取轻量组件/钩子（优先放 `src/web/components/`）：
  - `SwipeActionRow`：横向拖移、阈值、露出动作按钮、与纵向滚动冲突时取消
  - 复用/统一底部 `ActionSheet` 样式（项目、会话、消息可共用视觉）
  - `UndoToast`：若会话页已有内联实现，抽取或复制一致行为
- 不新增 npm 手势依赖，除非现有 pointer 实现证明不够稳

### D7. 长按全面退役

- 删除项目列表、会话列表、用户消息上的 long-press timer 逻辑。
- 测试改为覆盖左滑、点击 sheet、轻点工具条。

## Risks / Trade-offs

- [Risk] 移动端浏览器左滑与横向溢出/返回手势冲突 → Mitigation：仅在行内横向拖移超过阈值后接管；垂直移动优先交给滚动；提供归档 tab 点击 sheet 作为非手势兜底。
- [Risk] 用户不知道左滑 → Mitigation：首次归档成功 Toast 可带「可在归档中恢复」；归档 tab 点击路径保证可发现。
- [Risk] 消息轻点与文本选择冲突 → Mitigation：短按抬起打开工具条；明显拖选不打开；工具条打开时仍可关闭后选择文本。
- [Risk] 已归档不能进入后，用户想回看内容 → Mitigation：本次按产品规则不支持；若后续需要只读预览，另开变更。
- [Trade-off] Web 左滑实现成本高于按钮，但换来默认 UI 干净度。

## Migration Plan

1. 先落地共享原语与会话列表（最高频、约束最清晰）
2. 再改用户消息入口
3. 最后迁移项目操作到项目内并移除列表长按
4. 更新/替换相关单元测试
5. 无需数据迁移；回滚即为恢复长按入口（git revert）
