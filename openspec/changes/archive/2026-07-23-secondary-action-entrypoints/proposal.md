## Why

项目列表、会话列表和用户消息的次要操作目前主要依赖长按手势。长按可发现性差，且与滚动、文本选择冲突，在移动端 Web 上体验不友好。现在需要用更干净、可预期的入口替代长按，同时保持默认界面不堆每行菜单图标或顶栏「管理」模式。

## What Changes

- **会话列表（进行中）**：左滑露出「归档」按钮，再点执行；取消长按作为入口
- **会话列表（已归档）**：点击条目打开底部 sheet（移出归档 / 取消），也可左滑露出「移出归档」再点执行；**已归档会话不可进入聊天页**
- **项目列表**：取消长按菜单；列表点击仅进入项目；项目级操作（重命名 / 存储迁移 / 移除）收纳到项目内页面入口
- **用户消息**：取消长按菜单；轻点气泡进入选中态并展示操作工具条（复制 / 回滚 / Fork / 取消）
- 可逆列表操作（归档 / 移出归档）在执行后可用 Undo Toast（与会话内归档体验对齐）；高影响操作（回滚、项目移除）保留确认
- 长按触发操作菜单作为主入口全面退役（**BREAKING** 相对既有交互习惯，但不破坏 API）

## Capabilities

### New Capabilities

- （无）本次为既有能力的入口与交互语义调整，不新增独立业务域

### Modified Capabilities

- `thread-list-view`：会话列表归档/移出入口由长按改为左滑与点击 sheet；已归档不可进入会话
- `project-management`：项目操作入口由列表长按改为项目内入口
- `timeline-message-actions`：用户消息操作入口由长按改为轻点工具条

## Impact

- 前端页面与组件：
  - `src/app/projects/page.tsx`（项目列表长按退役，操作迁移）
  - `src/app/projects/[projectId]/page.tsx`（会话列表左滑/归档交互，项目内设置入口）
  - `src/web/components/Timeline.tsx`（用户消息点选工具条）
  - 可能抽取共享 `ActionSheet` / 左滑行 / Undo Toast 小组件
- 会话页顶栏 `⋮` 归档与 Undo Toast 既有能力可复用模式
- 后端 archive/unarchive/rename 等 API 不变
- 单测与集成测试需覆盖新入口，移除/替换长按相关断言
