## Why

当前会话底部发送区在移动端运行态仍保留禁用输入框、图片、全屏、重发和停止等多个控件，视觉上像被压缩的桌面工具条。用户真正需要的是明确知道 agent 正在生成，并能快速停止；空闲时则需要更直接地发送文字、发送图文和进入全屏编辑。

同时，普通输入框需要支持回车发送，减少键盘用户和外接键盘场景下的发送成本；多行编辑仍由全屏编辑器承担。

## What Changes

- 底部发送区 SHALL 按 thread 状态切换形态：空闲态显示输入 composer，运行态显示“正在生成…”状态栏和停止按钮。
- 空闲态 composer SHALL 保留图片入口作为一级操作，并保留文本输入、全屏编辑入口和发送按钮。
- 运行态 SHALL 不显示禁用输入框、图片入口、全屏入口或重发入口，只保留状态提示和中断操作。
- 普通输入框 SHALL 支持回车发送；空白文本、图片上传中或图片无文本时仍不得发送。
- 全屏编辑器 SHALL 继续把回车作为换行，不因普通输入框回车发送而改变。
- 「重发上一条」能力 SHALL 保留，但不再作为运行态可见控件；空闲态可通过更低优先级入口承载，避免挤占主发送路径。
- 不引入 breaking change；发送、图片上传、中断、重发相关 HTTP API 保持不变。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `chat-input-area`: 调整底部发送区的空闲态/运行态呈现、图片入口优先级、普通输入框回车发送行为，以及重发入口的视觉优先级。

## Impact

- 影响 `src/web/components/ChatInput.tsx` 的状态分支、键盘事件、控件布局和可访问标签。
- 影响 `src/app/threads/[threadId]/page.tsx` 中底部输入区预留高度、跳到最新按钮或 toast 的底部避让关系。
- 影响 `tests/unit/web-chat-input.test.tsx`，需要更新运行态断言并新增回车发送测试。
- 可能影响截图或浏览器验证基线，需要用移动端视口检查底部栏在空闲态、运行态、图片已选、上传失败和全屏编辑中的表现。
