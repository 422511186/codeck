## Context

`ChatInput` 目前在一个固定底栏里同时承载图片选择、文本输入、全屏编辑、重发上一条、发送/中断。空闲态下这些能力基本可用，但运行态下输入框被禁用，仍和多个低优先级按钮一起占据底部第一层视觉空间。移动端屏幕高度有限，底部栏越像工具条，越容易遮挡 timeline 并削弱“正在生成，可停止”的核心反馈。

现有 `chat-input-area` 规格已经把多行输入交给全屏编辑器，并要求运行态不暴露 steer。本变更沿用这个方向，把底部发送区设计成明确的状态机：空闲态是 composer，运行态是状态栏。

```text
空闲态
┌────────────────────────────────────────────┐
│ [图片]  [ 输入消息…………………        ⤢ ]  [发送] │
└────────────────────────────────────────────┘

运行态
┌────────────────────────────────────────────┐
│  正在生成…                         [停止] │
└────────────────────────────────────────────┘
```

## Goals / Non-Goals

**Goals:**

- 让移动端底部发送区在空闲态和运行态有清晰不同的视觉语义。
- 在空闲态保留图片入口为一级操作，支持文字和图文发送。
- 让运行态只表达“agent 正在生成”和“停止”两个重点，不展示不可用输入控件。
- 普通输入框支持回车发送；全屏编辑器继续支持回车换行。
- 保持现有上传、发送、中断、重发 API 不变。

**Non-Goals:**

- 不实现运行中 steer 或边生成边追加用户消息。
- 不允许仅图片无文本发送。
- 不重新设计 timeline、顶部 header、模型选择或 Plan/Build 控件。
- 不新增桌面端布局；所有判断默认面向手机浏览器。

## Decisions

### 1. 运行态切换为状态栏，而不是禁用 composer

选择：当 `running` 为真时，`ChatInput` 渲染独立的运行态状态栏，包含状态文案和中断按钮；不显示 textarea、图片、全屏、重发等控件。

理由：禁用 composer 暗示“输入能力暂时不可用”，但运行态用户最关心的是生成进度和停止操作。状态栏减少控件密度，也能释放底部水平空间。

替代方案：保留禁用输入框，只隐藏部分按钮。该方案改动小，但仍会让底部像不可用的输入区域，不能解决视觉语义混乱。

### 2. 图片入口保持一级操作

选择：空闲态底栏左侧继续显示图片按钮。图片是发送图文的前置入口，不折叠进更多菜单。

理由：用户明确要求保留发送图片入口；图文发送在移动端通常依赖相册入口，隐藏后会增加发现成本。

替代方案：用 `+` 菜单承载图片和重发。该方案扩展性更好，但对当前目标偏重，也削弱了发送图片的直达性。

### 3. 全屏编辑入口放在输入框内部或紧贴输入区

选择：全屏编辑入口仍是空闲态主路径的一部分，但视觉上应弱于发送按钮；实现时可以放进输入框内部右侧，或保持紧贴输入框的图标按钮，只要移动端底栏不拥挤。

理由：现有规格要求全屏编辑器，且多行编辑依赖它。视觉优先级应低于输入和发送，但不应消失。

替代方案：只在输入超过一定长度后显示全屏按钮。该方案能减轻默认密度，但会造成入口不稳定，用户较难学习。

### 4. 普通输入框回车发送，全屏回车换行

选择：普通 composer textarea 捕获 `Enter` 发送；全屏编辑器保持 `Enter` 插入换行。普通输入框如果需要换行，应引导用户使用全屏编辑器。

理由：现有移动端输入区规格强调底部单行/最多三行，不适合作为完整多行编辑面板。回车发送提高短消息效率，长消息由全屏编辑器承载。

替代方案：`Ctrl+Enter` 或 `Meta+Enter` 发送。该方案对移动端和普通键盘输入不够直接，也不符合用户本次明确需求。

### 5. 重发入口降级，不参与运行态

选择：重发上一条保留为静止时能力，但不在运行态显示，也不和发送按钮争抢主路径。实现时可保留为空闲态的次级图标、移动到更多入口，或后续由会话菜单承载；本 change 只要求它不出现在运行态且不破坏可重发流程。

理由：重发是恢复/编辑上一条消息的低频操作，运行态也不可用。它不应让底部第一层在最紧张的宽度里长期拥挤。

## Risks / Trade-offs

- [Risk] 运行态隐藏输入框后，用户可能不知道结束后还能继续输入。→ Mitigation：运行结束恢复 composer，状态文案保持简短明确，例如「正在生成…」。
- [Risk] 普通输入框回车发送可能让想换行的用户误发送。→ Mitigation：全屏编辑入口保留在输入路径中，规格明确全屏回车换行；测试覆盖全屏行为不变。
- [Risk] 底部栏高度变化影响 timeline 底部避让、跳到最新按钮和 toast。→ Mitigation：实现时同步调整或验证底部预留高度，在空闲态、运行态和带图片缩略图时检查不遮挡最后消息。
- [Risk] 重发入口降级后可发现性降低。→ Mitigation：保留可重发能力和测试，入口位置在实现中选择不抢主发送路径的方案。

## Migration Plan

1. 先更新 `ChatInput` 单元测试，明确运行态状态栏、回车发送、全屏回车换行、图片入口保留和重发能力。
2. 调整 `ChatInput` 渲染分支和键盘事件，保持 props API 不变。
3. 调整会话页底部避让样式，确保 timeline、toast 和跳到最新按钮不被新底栏遮挡。
4. 使用移动端视口做浏览器检查，覆盖空闲态、运行态、图片已选、上传失败和全屏编辑。

Rollback 可直接恢复旧的 `ChatInput` 运行态分支和测试断言；外部 API 未变化。

## Open Questions

无。产品决策已确认：运行态使用状态栏，图片入口保留为一级操作，普通输入框回车发送。
